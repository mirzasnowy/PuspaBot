Wiring yang dibangun (semua lewat parameter konstruktor / subclass resmi nanobot):
- `puspa/chassis/context.py` — ContextVar token izin turn ini (payload dict yang SUDAH diverifikasi; string mentah ditolak) + fallback baca `RequestContext.attributes["puspa_token"]` + `make_ledger_sink` (ledger -> callable `log(jenis, isi)`).
- `puspa/chassis/tools.py` — `PuspaTool(Tool)`: cek token (tanpa token -> tolak fail-closed) -> cek nama tool di `payload["tools"]` -> kalau tool punya manifes skill, `check_tool` (dengan verifikasi signature, lihat keputusan 7) -> kalau tool memetakan ke kind aksi keluar, lewat `Gate.request_approval` (tanpa gerbang -> tolak; kalau gerbang membuat permintaan, kembalikan error "Menunggu persetujuan" TANPA eksekusi) -> eksekusi tool asli -> hasil string dipindai injeksi (deteksi saja, dicatat di `tool_selesai`; pemblokiran tugas Pemeriksa fase 2) -> audit `tool_dipanggil` + `tool_selesai` (tanpa isi parameter — bisa berisi data sensitif).
- `puspa/chassis/registry.py` — `PuspaRegistry(ToolRegistry)`: `register` membungkus semua tool sekali (anti-bungkus-ganda); override `prepare_call` sebagai backstop (tool yang lolos tanpa bungkus tetap dicek tokennya, ditolak + dicatat).
- `puspa/chassis/hooks.py` — `PuspaHook(AgentHook)` observasi saja: `before_run` -> `tugas_dibuat`, `after_run` -> `tugas_selesai` + `pesan_agen` (dipotong 2000 karakter), `on_error` -> `tugas_gagal`. Aturan angka yatim (`finalize_content`) BELUM ditegakkan — fase 2.
- `puspa/chassis/skills.py` — `PuspaSkillsLoader(SkillsLoader)` override `_load_skill`: skill workspace/plugin WAJIB lolos `verify_skill` (tanpa `public_key` -> semua ditolak); skill builtin nanobot dipercaya sebagai bagian chassis.
- `puspa/chassis/session.py` — `bind_turn`: validasi sesi login (`validate_session`) -> terbitkan token izin agen Ed25519 (anggaran default 25 langkah / 100.000 token / Rp0, `tugas_id` opsional di payload).
- `puspa/chassis/sandbox_tool.py` — `SandboxTool(Tool)`: eksekusi kode lewat `puspa.sandbox.Sandbox`; kalau sandbox tidak tersedia -> `ToolResult.error` (tidak pernah eksekusi di host). Tool shell bawaan nanobot tidak masuk daftar token Puspa.

## Keputusan yang dicatat (butuh Nero hanya kalau ia tidak setuju)
1. **Tombstone tanpa UPDATE.** Definisi 2.3 melarang UPDATE/DELETE di tabel `kejadian` TAPI juga bilang isi kejadian dihapus diganti tanda hapus. Keputusan: hapus = append `tugas_dihentikan` dengan `isi={"dihapus": true}`; proyeksi menyembunyikan tugas. Append-only dipertahankan sebagai invarian yang lebih kuat.
2. **Limit Rp0 = dua cek independen.** Persetujuan DAN batas belanja dicek terpisah di gerbang; limit default Rp0 berarti pembayaran apa pun tetap diblokir sampai user menaikkan limit di Pengaturan (API `set_limit` tersedia; UI Pengaturan fase 2).
3. **Kunci dibuat saat runtime/tes**, tidak disimpan di file. Master key vault hanya dari env `PUSPA_VAULT_MASTER_KEY`; tanpa env, vault raise (tidak ada kunci default).
4. **DB tes tanpa password**: peer auth sebagai user OS (`root`) via socket; DSN default `dbname=puspa_test user=root host=/var/run/postgresql`, bisa dioverride env `PUSPA_TEST_DSN`.
5. **Urutan rantai ledger (menyimpang dari kontrak harfiah, perlu konfirmasi):** kontrak menulis rantai diurutkan `id`, tapi `id` memakai `gen_random_uuid()` sehingga tidak terurut waktu sisip — implementasi memakai urutan penyisipan `(waktu, id)` dan mendokumentasikannya di docstring `ledger.py`. Alternatif: id UUIDv7. Keputusan akhir di tangan parent/Nero.
6. **Gate butuh `public_key` untuk token string** (param opsional di luar `Gate(log, spending)` di kontrak): token string tanpa `public_key` ditolak, signature tidak boleh dilewati diam-diam. Token boleh juga diberikan sebagai payload dict yang sudah diverifikasi pemanggil.
7. **Celah `check_tool` — DIPERBAIKI 17 Nov 2026 ~14:20 WIB (bukan lagi tindak lanjut fase 2).** `check_tool(skill, tool, public_key=None)` sekarang WAJIB memverifikasi tanda tangan: `public_key=None` -> tolak fail-closed (`SkillRejected`); manifes dict diverifikasi signaturenya terhadap manifes unsigned; manifes dirpath dibaca dari disk lalu diverifikasi; baru setelah lolos, cek keanggotaan tool. Helper baru `_verify_manifest_dict`; `verify_skill` direfaktor memakainya. 5 tes baru di `test_policy.py` (tanpa public_key ditolak, manifes unsigned ditolak walau tool terdaftar, manifes diubah setelah tanda tangan ditolak, kunci salah ditolak, skill-dir unsigned ditolak) + 3 call site lama diperbarui. `tests/test_policy.py` + `tests/test_attacks.py` = 50 lolos.
