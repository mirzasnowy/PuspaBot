# Security Policy

## Supported Versions

| Version            | Supported |
| ------------------ | --------- |
| 0.1.0-beta and later | Yes     |
| Earlier versions   | No        |

If you are running an earlier version, please upgrade to the latest
release before reporting a problem.

## Reporting a Vulnerability

If you find a security vulnerability in PuspaBot, please do not open a
public issue.

Report it privately through GitHub private vulnerability reporting on
this repository: go to the Security tab and choose "Report a
vulnerability". This creates a private Security Advisory that only you
and the maintainers can see.

Please include as much detail as you can: what the problem is, where
it is, steps to reproduce it, and the impact you think it could have.

## What Happens After You Report

1. We will acknowledge your report and begin investigating it.
2. We will work on a fix and keep you updated on progress.
3. Once a fix is ready, we will release it and publish a Security
   Advisory describing the issue and the fix. We will credit you for
   the report if you would like to be credited.
4. Please do not disclose the vulnerability publicly until the fix
   has been released and the advisory is published.

We aim to acknowledge every report within a few working days.

## Scope

PuspaBot is software you run yourself, on your own machine or server.
Please test against your own local install only.

Do not probe the hosted PuspaBot service, do not run automated scanners
against it, and do not try to access other people's data.
Vulnerabilities found by probing the hosted service are out of scope
for this policy.
