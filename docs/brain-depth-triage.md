## VERY DEEP - in priority order

### Tier 1 - wedges + brain core, build first (6)

1. **HippoRAG** - Multi-hop retrieval via Personalized PageRank over an open knowledge graph. Mechanism: an LLM builds a schema-less KG at index time + PPR + HippoRAG 2 style re-ranking. Why deep: the price/fraud/service graph needs multi-hop answers (product → promo → seller → fraud report) that keyword+vector cannot do. Measured by multi-hop recall.
2. **Aider** - Surgical code edits (diff + repo map). Mechanism: repo map (structure summary) + generate/apply unified diff + lint/test after edit. Why deep: the harness today writes whole files; diff is what separates a toy harness from a real coding agent and makes self-develop reviewable. Measured by edit success rate + failed applies.
3. **SWE-agent** - Reproduce-first coding loop (read issue → reproduce with a failing test → fix → run tests). Mechanism: reproduction mandatory before fixing + proof of fix afterwards. Why deep: this is the core of trust in self-develop. Measured by % of tasks with reproduction first + regression rate.
4. **google/adk-python** - Hierarchical multi-agent + sessions + state + memory + tool confirmation. Mechanism: agent hierarchy, session/state store, memory service, tool confirmation. Why deep: PuspaBot is multi-agent (PuspaBot + 2 agents + Reader/Executor/Checker) but its hierarchy is still ad hoc. Measured by handoff correctness + state surviving across turns.
5. **NVIDIA NeMo Guardrails** - Input/output rails (Colang-style). Mechanism: programmable rails constraining topics, conversation flow, and tool use. Why deep: security is moat #1 and today's injection scan is still regex/keyword; rails make policy testable (Indonesian rules, spending limits, topics). Measured by passing the 8 attack paths + false positives.
6. **sigstore** - Signing foundation (keyless signing + transparency log) for community skills. Mechanism: keyless signing + transparency log for skill artifacts. Why deep: the trust moat (signed skills) today has no verifiable provenance chain. Measured by % of community skills with verified signatures.

### Tier 2 - brain depth, build second (12)

7. **hermes-agent (deepen)** - Auto-create + auto-repair skills + persistent user model. Mechanism: failing skill → diagnosis → rewrite → re-verify. Why deep: the loop exists but only drafts skills; repair is the real Hermes moat. Measured by repair success + skill reuse. Note: the brief says take it as a reference, not rebuild it.
8. **letta-code (deepen)** - Experience-to-code/procedure loop. Mechanism: task results change the agent's own procedures/prompts. Why deep: decay/contradiction today is lifecycle bookkeeping, not self-improvement. Measured by procedure quality over time. Build as ONE loop with hermes-agent, not two.
9. **LightRAG (deepen)** - Full query modes (local/global/hybrid/naive/mix) + incremental graph update. Mechanism: LLM-built entity/relation graph at index + dual-level retrieval in every mode. Why deep: the pattern exists for one mode only. Measured by retrieval recall/precision on the price graph.
10. **LlamaIndex (reranker only)** - Reranker after retrieval + query decomposition. Mechanism: cross-encoder rerank + query-engine decomposition. Why deep: retrieval precision is wedge accuracy. Measured by P@k on price queries. Scope: reranker only, not the framework.
11. **openai/codex (sandbox profiles)** - Sandbox profiles (read-only / workspace-write / full) + per-action approval. Mechanism: profiled sandbox + approval-before-write. Why deep: the harness executor today has one sandbox mode. Measured by approval granularity + escape-test results.
12. **KiloCode (modes)** - Sub-agent working modes (Architect/Code/Debug/Ask). Mechanism: agent behavior changes per task phase. Why deep: sub-agents today are fixed classes. Measured by task success per mode.
13. **AgentBench (held-out eval)** - Multi-environment benchmark task set (DB, KG, OS, WebShop shapes). Mechanism: held-out task set + scoring in the eval harness. Why deep: the 10 cassettes are a dev set; without held-out data, a 1.0 score proves nothing about generalization. Measured by held-out eval score.
14. **mem0 (deepen)** - Memory extraction quality + recall ranking. Mechanism: extraction (what becomes a memory, dedup, conflict at extraction) + ranked recall. Why deep: profile merge today is deterministic UNION. Measured by recall@k on episodic queries.
15. **graphiti (deepen)** - Temporal edges in the price/fraud graph. Mechanism: validity periods on graph edges + handling of expired facts. Why deep: prices and fraud reports are inherently temporal, but only the profile has validity today. Measured by stale-fact rate.
16. **snyk/agent-scan (CI scanner)** - Scan every community skill in CI before the signed-skill gate. Mechanism: scan for tool-poisoning / rug-pull / injection / toxic flow as a CI gate. Why deep: the 341 malicious ClawHub skills are exactly this threat. Measured by % of malicious skills caught before merge.
17. **ShishirPatil/gorilla (BFCL eval format only)** - Multi-turn function-calling eval tasks in the eval harness, AST-based checking of tool calls. Mechanism: BFCL task format (multi-turn, multi-step function calls with reference calls to check against). Why deep: PuspaBot's core is tool-calling and the harness has no structured tool-use eval; BFCL is the standard shape for it. Measured by tool-call accuracy on held-out BFCL-style tasks. Scope: the eval format only, not the gorilla model or training code. License verified Apache 2.0 on 18 Nov 2026. Caveat: only the root LICENSE was read; individual BFCL data files were not verified for separate terms.
18. **decolua/9router (router)** - Free LLM gateway: RTK tool_result compression, smart 3-tier fallback with real-time quota tracking, auto OAuth token refresh, cross-format translation. Mechanism: lossless compression of tool results before they reach the model (filters for git-diff, git-status, grep, find, ls, tree, dedup-log, smart-truncate, read-numbered, search-list; auto-detect from the first 1KB of each tool_result; fail-safe to the original text when a filter fails or the result grows), plus subscription to cheap to free fallback on quota exhaustion, 429 or error, plus per-provider quota tracking with reset countdown and cost estimate. Why deep: same problem space as PuspaBot's tiered router + BYOK; the compression runs on the task cycle path and the quota-aware routing deepens the router. Measured by the actual token saving on PuspaBot's own tool output (not the 20-40% claim) and by fallback correctness. Scope: the three mechanisms only, each as its own iteration. Out of scope: Caveman/Ponytail prompts, multi-account round-robin (Team tier later), cloud sync. License: 9Router itself MIT, verified 18 Nov 2026. Caveat: sub-projects RTK (rtk-ai/rtk), Headroom (headroom-ai) and Ponytail (DietrichGebert/ponytail) are separate repos with unverified licenses; read each LICENSE before adopting anything from them. Free-tier arbitrage is not the goal; the mechanisms are. Hard rule: compression must never change a meaningful number (orphan-number rule) - dedup and truncate must not drop a number the Checker or the evidence ledger needs.

### Tier 3 - ecosystem / model / research, build third (3)

19. **openclaw (marketplace)** - ClawHub-compatible skill marketplace + discovery + trust scoring. Mechanism: registry, search/discovery, trust score, signed distribution. Why deep: the distro thesis lives or dies on the skill ecosystem. Measured by trusted skill installs. Post-MVP (community skills are phase 6).
20. **Sahabat-AI (fine-tune)** - Agentic tool-calling fine-tune on top of the Indonesian base. Mechanism: fine-tune + Indonesian tool-calling eval. Why deep: layer 1 of the 5 Indonesia layers in the brief. Measured by Indonesian tool-call accuracy. Post-MVP, needs GPU + data.
21. **gpt-researcher (cited synthesis)** - Researcher sub-agent with cited synthesis. Mechanism: plan → browse → synthesize → cited report (cited JSON only). Why deep: Researcher is 1 of the 6 roles and its answers need checkable citations. Measured by citation accuracy.
